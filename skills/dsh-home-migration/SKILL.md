# DSH_HOME 迁移与磁盘治理

## 适用场景

- 系统盘余量告急，DSH 工具开始报 `ENOSPC` 写入失败。
- 想在不破坏 DSH 既有读取路径的前提下把数据目录搬到数据盘。

## 前置条件

- 目标盘有足够空间；已统计源目录文件数用于迁移后校验。
- 确认 DSH 桌面版是以**进程级环境变量**设置 `DSH_HOME` 的。

## 操作步骤

1. 关闭 DSH。
2. 把 `$DSH_HOME` 目录整体复制到数据盘目标目录。
3. 在原路径建立 Junction 指向新目录：`mklink /J <原路径> <新路径>`（**不需要管理员权限**）。
4. 启动 DSH，按下方三项校验。

## 验证（三项都要过）

1. **文件数一致**：源与目标逐层比对，缺失必须为 0。
2. **写入穿透正常**：通过原路径写一个文件，确认落到数据盘真身。
3. **进程仍按原路径读 profile**：确认 DSH 仍以原路径访问 profile，行为无变化。

## 风险与边界

- **最大坑：清理时不要经 Junction 路径删。** 经联接删除会跟着删掉数据盘真身目录。要删就**直接删数据盘上的真身**。
- 迁移后手工 pnpm 的 store / virtual-store 前缀路径要跟着核对（见 `dsh-profile-plugin-install`）。
- 迁移前保留旧副本，直到校验通过且用户确认后再删。

## 回滚

删除 Junction，把数据盘目录复制回原路径即可；旧副本在确认前不要清理。

## 备注

- 迁移后系统盘余量回升是可验证的收益指标；但注意区分**本次操作带来的释放**与其他缓存（例如显卡着色器缓存）的自然变化，别把功劳记错。
- 只迁移数据目录，不要顺手改 profile 配置。
- ``$DSH_HOME`` 迁移会一并带走 `skills/`、`storages/`、`sessions/` 等数据目录；经 Junction 旧路径仍可读，写入都落到数据盘真身。
