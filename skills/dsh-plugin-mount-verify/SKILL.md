# 验证插件是否真的挂载

## 适用场景

- 刚改过 `dsh.profile.bundles` 或手工装了插件，想确认是否生效。
- 想探测本地 DSH 服务状态，但所有请求都被鉴权挡住。

## 核心判据（不要用 HTTP 状态码）

DSH 对**任何** `/api/*` 都返回 `401 unauthorized`（通用鉴权，未带 token 无法探测）。
因此状态码**完全不能**用来判断插件是否挂载，看到 401 不代表服务或插件有问题。

可靠办法：

1. 改完 `bundles`。
2. 观察 `$DSH_HOME/storages/<插件单元>.json` 是否被新建或刷新。
3. **落盘时间即挂载时间**。

## 验证

- 对照文件名与插件单元的映射（例如桌宠类插件的单元文件名与其包名不同），确认看的是对的文件。
- 同名文件被刷新 = 插件已加载；文件从未出现 = 没有真正挂上。

## 风险与边界

- 改 `bundles` 会触发自动重组合，**无需重启**；但改其他层（应用外壳、非 client-plugin 的包）仍需要重建对应产物并刷新页面。
- client-plugin 的热更新只有在配套的 dev 监听（如 `dev:web`）同时运行时才免刷新；否则仍需刷新页面。

## 回滚

本技能只读，不产生改动；若验证结论是「没挂上」，回到 `dsh-profile-plugin-install` 或 GUI 处理。

## 备注

- 「401 是正常的」这一条最值得写进脑子，能省掉大量无效探测。
- 别为了验证去翻源码或解压打包产物，落盘时间就足够。
- **单元名映射实例**：`dsh-dfy`（大肥鱼桌宠）→ `$DSH_HOME/storages/dsh_whale_pet.json`。插件包的 `name` 与 storages 单元文件名并不一致，别找错文件。
